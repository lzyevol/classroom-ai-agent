## 一、项目背景

### 1.1 行业现状

随着大模型、机器人、自动驾驶等领域的快速发展，"具身智能"已成为人工智能领域的重要前沿方向，越来越多的高校将其纳入课程体系。然而，该课程具有如下特点：

- **概念密度高**：涉及环境感知、任务规划、运动控制、多智能体协同等多个子领域
- **知识关联性强**：前置知识（如深度学习、强化学习）与应用章节深度耦合
- **实践门槛高**：真实机器人实验设备有限，学生缺乏动手验证的条件

### 1.2 教学痛点

| 角色 | 痛点 | 典型场景 |
| --- | --- | --- |
| 学生 | 遇到问题无法及时获得有教材依据的讲解；不知道先学什么、复习什么；做题后只有对错，缺少错因分析和后续建议 | 课后自主学习、考前复习 |
| 教师 | 难以汇总全班高频问题和共性薄弱点；教学调整缺少连续数据支撑 | 备课、组织练习、教学反思 |

### 1.3 项目定位

本项目基于 RAG（检索增强生成）技术和知识图谱，构建面向"具身智能"课程的教学智能体。系统不替代教师，而是：
- 为学生提供**可信、及时、可追溯**的学习支持
- 为教师提供**数据驱动、可解释**的学情分析

### 3.2 核心思路

1. **教材知识图谱化**：将教材通过 PaddleOCR-VL 识别 + DeepSeek 抽取，构建结构化知识图谱（788 实体、3204 关系、426 原文 Chunk、140 章节），存储在 Neo4j 中
2. **RAG + 知识图谱检索**：学生提问时通过 LLM 提取关键词 → Neo4j 参数化查询命中知识点和原文片段 → 一跳关系扩展上下文
3. **LLM 约束生成**：严格 Prompt 约束 + 结构化 JSON 输出，AI 只能基于检索到的教材上下文回答，无依据时明确告知
4. **后端组装引用**：citations 由后端从 Neo4j 直接组装，LLM 不参与引用生成，确保引用 100% 可溯源
5. **前端复用 OpenMAIC**：AI 老师讲课形态（幻灯片 + TTS + 打断问答 + 课中小测），专门问答和练习独立页面
6. **练习与批改闭环**：LLM 按知识点/题型/难度生成题目 → 客观题规则秒判 + 简答题 LLM 评分点批改 → 掌握度由规则引擎（正确率阈值）决定，不由 AI 拍板
7. **学习推荐**：规则触发（连错 2 道、正确率 <60%、多次问同一概念）→ LLM 把触发原因和建议转成人话，输出复习位置和建议题型
8. **教师学情驱动**：学生作答/问答/掌握度数据 SQL 聚合 → LLM 生成可编辑教学建议（补讲/练习/关注学生），教师决定是否采纳
9. **题目质量管控**：AI 生成题目进"草稿"状态 → 教师审核编辑后才发布到正式题库，正式作业优先用已发布题目
10. **权限隔离**：学生只看自己数据、教师只看负责班级、管理员管课程和账号；所有关键操作写审计日志

## 八、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
| --- | --- | --- | --- |
| DeepSeek API 不稳定/超时 | 问答和批改不可用 | 中 | 重试机制（最多 3 次）+ 超时降级提示 + 可切换备选模型 |
| 教材 OCR 解析质量不足 | 检索不到内容或引用错误 | 低（已验证） | 已通过 PaddleOCR-VL 1.6 处理并人工抽查，质量可控 |
| LLM 回答不稳定/幻觉 | 学生看到错误信息 | 中 | Prompt 强约束 + 结构化 JSON + 无依据时明确提示 + 教师审核机制 |
| Neo4j 性能瓶颈 | 查询变慢 | 低 | 当前数据量小（1354 节点），加索引已足够；后续可加向量检索 |
| 前端 OpenMAIC 改造工作量超预期 | 延期 | 中 | MVP 优先用静态原型演示核心流程；第三阶段再做正式对接 |
| 成员时间冲突 | 进度延迟 | 中 | 每周同步进度；按优先级裁剪 P1 功能；核心闭环（P0）优先保证 |

## 九、Demo 演示计划

### 9.1 演示场景（5 分钟完整流程）

1. **学生上课**：打开章节学习页 → AI 老师讲课（幻灯片 + 语音） → 课中小测（答对继续/答错重讲）
2. **学生打断提问**：听不懂举手打断 → AI 暂停回答 → 展示教材依据引用 → 继续听课
3. **专门问答**：学完后深入追问 → 多轮对话 → 引用可展开查看原文
4. **章节练习**：选择知识点/题型/难度 → 做题 → 提交 → AI 批改 → 评分点覆盖展示
5. **学习推荐**：连续答错后触发推荐 → 建议复习对应章节 → 跳转

### 9.2 技术验证点

- 问答有教材来源、无依据不编造
- 引用点击可跳回原文
- 简答题有评分点逐项展示
- 图片正常加载
- 全部走真实 Neo4j + DeepSeek（非纯 mock）

## 十、总结

本项目通过"知识图谱 + RAG + LLM 约束生成"的技术路线，解决具身智能课程中学生自学难、教师学情不透明的核心痛点。当前已完成数据层（Neo4j 知识图谱）和后端 MVP（问答 + 教材接口，18 测试全通过），前端原型已可交互演示。下一步重点是练习/批改闭环和前端正式对接，按计划 4 周内交付完整产品。

### 11.3 当前数据设计补充

- 已新增 teaching_assignments 与 assignment_students，用于保存教师作业定义、学生领取状态、开始时间、提交时间、干预前后掌握度、作业成绩等信息。
- practice_sessions 已关联 assignment_id，使教师任务可以复用既有练习生成和批改流程。
- 教师作业默认按小节范围组题；knowledge_point 字段保留以兼容历史专项任务和后续诊断需求。
- 班级小节掌握情况从作答记录聚合，同时结合题库中的可用客观题数量，为教师提供可布置任务的小节列表。

### 11.4 已确认的产品交互原则

1. 学生可以始终进入自主章节练习，教师作业不应阻断自主学习。
2. 多项教师作业在同一张章节练习卡片中展开选择，不通过增加多个首页卡片制造信息噪声。
3. 教师教学干预以章节/小节为主维度；知识点用于解释小节薄弱原因和个性化复习。
4. 学生首页和学习中心优先呈现可执行动作，不展示知识图谱实体数、关系数等系统内部技术指标。

### 11.5 后续实施重点

- 将学习中心进一步收敛为“唯一下一步动作、需优先复习小节、错题处理、历史与知识点下钻”。
- 完善作业截止提醒、作业详情、逾期状态和多小节组合任务。
- 扩充课程章节、课件和题库资源，并完成三端核心路径的回归测试。
- 完成部署说明、环境变量说明、容器化与交付验收材料。

## 十二、学习中心交互落地记录（2026-08-05）

学习中心当前按照以下信息优先级实现：

1. 下一步行动：教师作业进行中时优先提供继续完成入口；没有教师任务时使用学习推荐或自主练习入口。
2. 小节掌握：以小节为主要学习分析单元，优先突出需要复习和正在巩固的内容。
3. 错题处理：按小节聚合错题，提供集中复习入口，具体题目默认收起。
4. 数据下钻：知识点诊断和完整练习历史放入折叠或次要区域。

学习中心不再把客观题正确率与总体掌握度并列作为主要指标，也不再展示知识图谱实体数、关系数等对学生行动没有直接帮助的系统指标。已学习小节只展示后端统计的实际学习数量，避免把练习掌握数据集合大小误当作课程总小节数。
