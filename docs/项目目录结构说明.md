# 项目目录结构说明

更新时间：2026-08-05

## 当前运行代码

以下目录属于当前项目的正式运行和维护范围，不要随意移动或重命名：

- app/：FastAPI 后端路由、服务、Schema、数据库、知识检索和外部模型客户端。
- frontend/：Next.js 学生端、教师端和管理员端前端。
- config/：知识图谱和课程配置。
- data/：SQLite 演示数据库、课程资源、题库和处理后的图谱数据。
- prompts/：问答、课件、练习和批改相关 Prompt。
- scripts/：Neo4j 导入、题库播种、课程资源处理和验证脚本。
- tests/：后端和作业流程自动化测试。
- docs/：正式产品文档、实施方案、任务进展和历史文档。

## 归档内容

与当前启动路径无关的历史代码、本地副本和原始材料统一放在 archive/ 下：

- archive/legacy-backend/：历史后端版本快照。
- archive/upstream/：OpenMAIC 上游参考代码。
- archive/handoff/：本地 AI 交接记录。
- archive/logs/：历史运行日志。
- archive/source-material/ocr/：原始 OCR 导出文件。
- docs/archive/：旧版项目进度文档。

归档目录不会参与当前项目启动，也不会作为正式运行代码提交。

## 本地运行环境

以下目录和文件属于本地运行产物或环境，不属于项目源码：

- .venv/：Python 虚拟环境。
- node_modules/、.pnpm-store/：前端依赖和包管理缓存。
- .pytest_cache/、.tmp/：测试和临时文件。
- .env：本地密钥和服务地址配置。
- backend/live 日志：本地服务运行日志。

这些内容由 .gitignore 忽略，不能提交到仓库。

## 整理原则

1. 当前启动代码只从根目录的 app、frontend、config、data、prompts 和必要脚本读取内容。
2. 不把历史版本直接删除，统一保存在 archive/ 便于回溯。
3. docs/ 保留正式文档；旧文档移入 docs/archive/，不和当前进展混在一起。
4. app/ 和 frontend/ 内部代码必须先经过引用检查，再决定是否归档，不能仅凭文件名移动。
